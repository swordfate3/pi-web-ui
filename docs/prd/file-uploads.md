# 工作区附件上传

## 用户目标

在手机／桌面网页选择图片、PDF、文本或其他普通文件，保存到当前 Pi 的本地工作区，再把路径发送给 Pi。项目和附件留在运行 Pi 的机器；阿里云网关／Hub 只转发流量。上传成功不表示模型已经读懂文件，不自动执行、解压或解析文件。

## 交互

- 输入框使用回形针及始终可见的“上传文件”文字，支持文件选择、拖入和粘贴图片；保留原始字节，不把文件转 Base64 塞进聊天消息。
- 默认每文件最多 **1 GiB（1,073,741,824 字节）**，最多选择五个附件。服务端可配置大小上限，硬上限 **8 GiB**；浏览器先允许硬上限内选择，发送时按服务端实际配置检查。选择时只展示附件，不立即写磁盘。
- 点击发送后，先分块校验文件，再以 **8 MiB** 分片逐个上传并展示进度；全部完成完整性校验和保存后才发一条 Pi 消息。仅附件也可提交。浏览器和服务器均不把整个大文件放入内存。
- 可取消校验或上传；失败或取消保留当前页面草稿及附件，便于重试。已确认分片暂存，重试只补传缺失部分。成功的文件已经落盘，不因取消另一文件、移除附件或关闭页面而被删除。
- 刷新页面后需要**重新选择同一原文件并点击发送**，校验后可恢复当前运行期内已确认的分片。续传仍需重新读取并校验原文件内容，节省的是网络重传而非本地校验时间。刷新不保存浏览器文件访问权、草稿或附件列表。文件名、大小或内容不同不会续接旧文件；不把两份文件拼接。
- 临时续传只在当前 Pi 运行期和会话有效。会话切换、扩展重载、停止服务后重新开始上传，不承诺跨进程重启恢复。未完成上传空闲一小时过期，正常清理删除临时文件；进程崩溃遗留的临时文件需要用户检查清理，不自动扫描其他进程的目录。
- 已上传文件可用于当前页面重试发送，收据短时有效。明确的交接前拒绝可重试；Pi API 返回不代表已接收，服务端最多等待 8 秒确认当前会话的用户消息。交接后结果不明时明确报错并锁住收据，先检查会话或手动引用已保存文件，不允许用同一收据盲目重发。
- 正在运行模型时附件提交提示等待；不将附件意图放入可能跨会话的文本队列。
- 发生会话切换、扩展重载或路由交接时取消尚在上传的操作并隔离旧收据，不自动向新会话重发旧附件。已经 dispatch 给 Pi 的异步提示无法通过上传取消撤回；尤其第三方异步 hook 与 reload 的交错不在已验证范围，发送结果未知时先检查会话。
- 图片以文件路径提供给 Pi，Pi 可按需使用读取工具查看；其他格式能否解析取决于工具和模型。旧版大 Base64 图片直传不作为新 UI 的发送路径。

## 保存位置

```text
<当前工作区>/
  .pi-uploads/
    <会话 ID>/
      <随机上传 ID>/
        原文件名.pdf
```

原文件名支持中文。服务端生成完整保存路径；浏览器不能任意指定目录。每个文件独立随机目录，重名不会覆盖。文件为私有普通文件，不跟随符号链接。保存到容器工作区仅在该工作区具有持久化挂载时跨容器重建保留。

持久附件不自动清理，也不自动加入 `.gitignore`，避免悄悄改变项目版本控制策略。用户负责按项目需要忽略、备份和清理 `.pi-uploads/`；删除会使旧对话中的附件引用失效。

## 协议边界

1. `prepare_upload({protocol:2,filename,size,sha256,chunkHashes,sessionId,runtimeId})` 经现有 WebSocket 验证当前会话／运行期，返回授权、相对路径、服务端上限、固定分片大小、下一个分片序号和已完成状态。全文件／分片哈希均为小写 SHA-256；0 字节文件的分片列表为空。重复准备同一个文件发现已有进度，不绕过交接状态。
2. 浏览器对 `/api/uploads/<uploadId>/chunks/<index>` 执行同源 HTTP `PUT` 原始分片；Hub 原有 `/s/<generation>/` 代理转发流。每片长度必须精确，最后一片可不足 8 MiB。文件体不走 16 MiB WebSocket 消息通道。
3. 服务端逐片核验实际大小及哈希，只有完整且正确的分片才推进序号。断开或校验失败不丢之前确认的分片；重复分片不重复追加。失败后客户端重新查询确认进度，不猜测上次请求是否成功。
4. `complete_upload({uploadId,sessionId,runtimeId})` 再核验完整大小及 SHA-256，无覆盖原子发布后返回完成收据。未完成文件不能交给 Pi，不能仅凭最后一片请求成功宣称全文件成功。
5. 浏览器发送 `prompt({message,uploads:[uploadId],sessionId,runtimeId})`。后端只接受当前 scope 已完成且未交接的收据，并追加服务器生成的文件路径给 Pi，不信任浏览器传入的路径。附件只允许 idle 发送，compaction、忙碌、无模型或无法解析凭据时预检拒绝。
6. 收据在 preflight 前原子预留，防止多网页重复交接；只有匹配当前 scope、完整用户文本及唯一附件路径的 Pi `message_start` 才消费并确认。8 秒未确认表示状态未知，不等于 Pi 拒绝，也不表示后续生成成功。迟到的匹配仍可结算，但服务端不会自动重发。

兼容旧客户端：不带 `protocol:2` 的旧 prepare／单次原文件 PUT 仍受 **50 MiB** 限制。新客户端需要新版后端，不通过静默降级掩盖扩展未重载。

## 配置

启动 Pi 前设置字节数（不改变已运行进程）：

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PI_WEB_UPLOAD_MAX_BYTES` | `1073741824`（1 GiB） | v2 单文件上限，硬上限 8 GiB |
| `PI_WEB_UPLOAD_MAX_PENDING_BYTES` | `2147483648`（2 GiB） | 当前实例所有未完成文件的声明大小总和 |

调大单文件上限时也应检查暂存总额，否则总额先到限会拒绝准备文件。暂存配置最多 128 GiB（16 个收据 × 8 GiB），不是建议值；无效或非正整数配置使用默认值，超硬上限的有效值被收紧至硬上限。设置的是资源边界而非预分配磁盘保证；还需实际磁盘容量和工作区权限。

## 访问与资源保护

- 保留现有 Hub 登记 proof、会话 generation、Origin/Fetch Metadata 与同源边界；Hub 没有自己的网页登录，仍需可信 HTTPS 登录网关。
- 路径遍历、绝对路径、符号链接父目录／目标、隐藏文件名、控制字符和平台保留名称拒绝；不扫描内容，也不能识别所有机密或恶意文件。
- 同时约束单文件大小、空闲时效、活跃写入并发、收据数量及未完成文件的**声明大小总和**。默认暂存总预留 2 GiB，避免大量只上传一片的文件绕过限额。完成文件不计入临时额度，也不自动删除。
- 配额为单 Pi 扩展实例内的资源保护，不是跨进程、跨工作区或累计成功文件的持久磁盘配额。达到额度、磁盘不足或权限失败时明确拒绝，不静默截断或删除用户成功文件。
- 不保证抵御同 OS UID／工作区管理员并发更换目录，不承诺扫描病毒、检测所有敏感内容或无限磁盘配额。不要向不可信用户开放 Pi 控制界面。
- 当前 Hub HTTP 代理保持 30 秒上游 socket 空闲超时和 Node 的完整请求时限（默认约 5 分钟）。分片降低单请求体积，但不承诺任意慢网络都能成功；连接中断后重传未确认分片。无 Content-Length 的 HTTP chunked transfer 仍拒绝——这与应用层 8 MiB 分片不是同一回事。
- 现有下载端点默认拒绝隐藏目录，因此 `.pi-uploads/` 下的文件不会仅凭聊天路径变成可下载文件；上传与下载权限不互相放开。

## 验证要求

后端纯测试覆盖字节／哈希完整性、顺序与重复分片、大小边界、0 字节、超限、断开保留确认进度、过期／停止清理、路径／符号链接、收据和生命周期。真实 Pi 直连与预构建 Hub 集成验证大于旧 50 MiB 上限文件、路径消息及错误边界；浏览器验证中文文件、原始图片、多分片、多附件、取消／刷新后重新选文件续传、进度及真实工具读取。桌面与手机截图人工检查，独立于功能 E2E。完整安装后的回归必须覆盖新增后端源文件的分发清单。证据以本轮验证报告为准，旧版报告不冒充新版通过。
