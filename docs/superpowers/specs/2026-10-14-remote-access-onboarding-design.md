# 远程访问引导与登录信息管理

日期：2026-10-14。状态：待用户审阅，尚未实现或部署。
开发分支：`codex/portable-web-connection`。

## 已确认的目标

- 用户安装扩展后，能找到远程访问向导，不必先理解 WSL、socket 或 Docker 挂载。
- 第一版生成可审查的部署脚本，由用户确认并执行；扩展不直接登录服务器执行管理操作。
- 阿里云是说明和部署模板支持的服务器场景，不是强制依赖。
- 首次部署自行设置登录信息，不能提供固定的默认用户名或密码。
- 用户知道如何修改账号、修改密码以及忘记密码后恢复访问。
- 保留现有阿里云部署，不擅自改密码、重启隧道或终止 Pi 会话。

## 当前实现与问题

现有扩展已经具有本地监听、端口递增、可配置公网地址、原生会话登记和子路径支持。
尚没有部署向导、网关安装程序或账号管理。

`extensions/mirror-server.ts` 的 `get_auth` 返回未配置，`set_auth` 明确拒绝操作。
网页现有“需要登录”开关不能管理外部网关，应避免把它当作可用的远程账号管理入口。

本用户现有手机入口由远程 Caddy 执行认证；本地登录记录不是服务器认证配置的权威来源。
仅修改本地记录不能算作密码修改成功。现有登录文件和管理员私钥不交给 Pi 进程。

## 第一版范围与边界

实现扩展内的引导、非敏感配置、部署材料生成及可解释的验证结果。
新部署模板必须明确全部依赖，不得把“需要用户自行准备 WSL 服务”隐藏在步骤中。
现有部署采用接入模板，不覆盖无关站点或共享服务。

第一版可执行服务器模板面向 Linux、OpenSSH 和 Caddy；先检查适用环境再显示执行步骤。
模板不能假定存在 Docker、特定 home 路径或本用户域名。
本地向导不依赖 WSL。Windows/macOS 的服务安装与自动启动未实现时必须明示不支持，
而不是复用 Linux 命令并宣称跨平台可用。

多会话部署需要匹配现有登记协议的独立路由服务。
若新部署模板没有提供该组件，不得标为“新部署完成”，只能支持现有兼容网关接入。
部署材料与路由服务应单独分层，不能把管理员权限放进模型工具或普通 Pi Web 请求。

## 界面与流程

### 入口

网页设置中增加“远程访问”和“登录管理”，均提供简体中文与英文。
首次打开提供可跳过的引导提示；以后可随时重新进入，不反复强制弹出。
Pi 终端另提供能定位到引导页的入口，不能要求先接通公网才能配置公网。

### 远程访问向导

1. 选择本机、可信局域网或远程服务器。
2. 远程模式选择“新部署”或“接入已有部署”。
3. 填写服务器地址、SSH 用户、端口、域名、入口及部署环境。
4. 展示所需组件、配置去向、权限、端口及受影响服务。
5. 生成部署材料，预览后由用户下载并在适用环境执行。
6. 展示分项验证结果与对应手机入口，不推测其他会话链接。

不要让用户把私钥、服务器 root 密码、网页登录密码或模型 API key 填入表单。
非敏感信息保存为独立的、可版本化的部署配置，不覆盖模型或现有扩展配置。
只有显式应用才更新 Pi 连接配置；取消、失败、刷新或重复打开不会修改配置。

## 登录信息管理

### 首次设置

- 明确区分服务器 SSH 用户和手机网页登录账号。
- 用户指定网页登录账号；没有固定账号或预置密码。
- 密码由部署脚本在用户终端交互输入并确认，不进入浏览器、模型、剪贴板或生成脚本正文。
- 服务器保存认证所需的密码哈希，不生成明文密码记录供扩展读取。
- 配置认证和 HTTPS 完成前，不把原始 Pi Web 监听暴露到公网。

### 修改账号或密码

- “设置 → 登录管理”展示管理方式、站点、账号（如已知）和明确操作入口，不展示密码。
- 新部署与已有 Caddy 部署均生成专用修改脚本；操作针对确认的站点和账号。
- 修改密码在用户终端完成；修改账号要求用户确认旧账号如何处理。
- 脚本备份相关站点配置、校验候选配置、应用修改；失败时保留或恢复原配置。
- 不覆盖其他站点、其他认证账号或共享服务配置。
- 界面区分“已生成、待执行”和“已验证”；不能声称生成脚本即修改成功。
- 用户执行后，以新账号实际认证验证成功作为生效依据，而不是读取本地登录记录。
- 提示浏览器可能需要重新登录，且共享入口账号变更可能影响所有 Pi 会话。

### 忘记密码

- 登录前不提供无凭据的公网重置接口。
- 部署材料中附带独立恢复说明与重置脚本，用户可通过自己持有的服务器管理权限执行。
- 登录管理入口解释该路径，即使用户无法登录 Pi Web 仍可恢复。
- 恢复脚本不会把网关临时切到无认证状态，也不挂载管理员凭据给 Pi。

### 现有部署迁移

- 接入前识别认证在网关还是其他受支持服务，不凭本地缓存推断服务器当前状态。
- 保留旧账号密码；只有用户显式执行修改脚本才变更。
- 原生登记与旧注入式登记不能同时启用。
- 缺少 Docker 挂载时解释需要重建哪个容器，不自动关闭运行会话。
- 用户现有服务的实际认证方案应先检查，非模板支持的方案提供说明而不生成危险改动。

## 安全与错误处理

- 模板值采用严格校验和正确引用，拒绝路径穿越、换行及 shell/配置注入。
- 不通过网页提供任意 SSH 执行、任意文件写入或管理员命令接口。
- 如果部署材料需要管理权限，提前列出确切目标、备份和回滚步骤。
- 公网探测由浏览器访问用户指定入口，或由用户运行检查脚本；
  不新增可访问任意内网地址的服务器端代理探测接口。
- 认证、网络、TLS、WebSocket 和会话租约错误分别显示，不用通用“连接成功”掩盖失败。
- 未执行、没有权限或无法验证时如实标为“待执行/无法验证”。
- 多会话链接使用实际登记 generation，旧链接不自动指向其他进程。

## 验收与测试

- 默认配置不含账号密码；向导可跳过并从设置重新打开。
- 新部署和已有部署接入流程不同，脚本生成不会执行远程操作。
- 生成脚本没有明文密码、默认密钥或本用户机器专用路径。
- 账号、域名、端口、路径等输入的非法值及注入尝试被拒绝。
- 模板语法、备份、校验失败及回滚路径在隔离测试环境验证。
- 修改密码的正例为新凭据可登录、旧凭据失效；失败不得破坏原认证。
- 接入已有部署不改变现有密码；修改本地登录记录不被当作认证变更。
- 忘记密码路径不依赖能够登录网页。
- HTTP、静态资源、WebSocket、子路径、多会话失效与端口递增分别验证。
- UI 使用真实 Pi 的浏览器测试并检查桌面和手机尺寸截图。
- 构建、类型检查和静态检查通过；报告区分本机、隔离网关和真实手机验证。

## 明确不在本次自动执行的操作

不部署或重启用户阿里云服务器，不修改现有密码，不开放防火墙，不调整 Docker 安全权限，
不安装到共享 Pi 卷，不推送或合并分支。以上均需后续明确授权。
