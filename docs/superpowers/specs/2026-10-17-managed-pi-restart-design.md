# Hub 提交受控 Pi 进程重启

日期：2026-10-17。状态：用户已批准设计，实施和安全复审中；没有生产部署。

## 1. 目标与批准范围

用户希望在手机 Hub 页面提交重启，使正在运行的 Pi 加载已经安装的新版本，
并继续原来的对话，不必回到电脑重新执行 pirun。用户已同意推进前述
“Hub 提交、门控授权、保留容器并重启指定 Pi 进程”的方向。

本次先同步远程，再设计实现。同步基线为 origin/main
`39176c9f973ea82f4017c76c8e13e5b29cf93236`；本地 main 已快进到该提交。
功能工作分支为 `codex/pi-runtime-restart`，不直接改写远程 main。

完成的含义：选定 Pi 的旧进程正常退出，新进程加载已安装的 Pi/扩展，
确认恢复准确的会话和分支，重新登记到 Hub，浏览器接续。
不能用 Docker running、磁盘版本或 HTTP 200 代替上述验收。

## 2. 已核对的现状

- Pi 程序位于 `/home/node/.local`，由 `pi-runtime` 卷持久化；其余现有卷不变。
- `pi-entrypoint` 同步 SSH 和模型配置后直接 `exec pi "$@"`，没有进程管理层。
- pirun 前台执行 Compose run，启用 `--rm`；启动脚本退出会撤销 Hub run 凭据，
  并执行附件生命周期清理。因此不能假定 Docker restart 能保持整个交互生命周期。
- Hub 目前管理登记、门户和 HTTP/WS 转发，不负责启动 Pi 或调用 Docker。
- 门控目前处理 Hub/镜像部署，没有 Pi 进程生命周期接口。
- Hub 已有绑定具体 run 的浏览器 handoff，但浏览器普通接续预算只有约 15 秒。
- SDK 提供 idle/pending 查询、准确 sessionFile/sessionId/leafId 和关闭事件。
  不能仅据 `shutdown()` 的类型声明推断外部 WS 回调能立即完成关闭；
  已读的 TUI 实现只设置 shutdownRequested，需用真实 Pi 测试关闭路径。

## 3. 方案选择

### 推荐：同一容器内受管重启 Pi

Hub → 专用的门控生命周期申请 → 指定容器内固定管理器 → 优雅退出并重新启动 Pi。

保留容器 ID、工作区、挂载、独立 Hub 凭据及前台终端连接。
管理器存活期间 pirun 不退出，不触发撤销和附件清理。

### 不采用：直接 Docker restart

现有前台连接、清理和恢复协议尚未配套；直接重启不能证明原会话恢复。
新能力不提供任意容器重启或批量重启。

### 暂不采用：全部迁为后台服务容器

可以另行实现长期后台工作，但会改变终端退出行为、附着和回收方式，
不是此次加载已安装更新所必需。

## 4. 组件边界与身份

### 包内 Hub 和 Web 扩展

- Hub 门户卡片显示运行版本、可否受控重启、当前操作阶段及失败原因。
- 增加“应用已安装更新并重启此 Pi”确认操作；明确只影响选定 Pi，
  不执行 npm update、不重启 Hub、不重建镜像。
- 提供有大小限制的能力/状态协议；浏览器不得提交命令、PID、容器名称、
  session 文件路径、镜像、挂载或环境变量。
- Web 扩展使用 fresh `latestCtx` 检查状态及生成恢复快照；
  不在跨重启、resume、reload 的异步闭包内保留失效上下文。
- 包自身保持可独立使用；没有配置生命周期 provider 时显示不支持，
  不依赖此用户的 WSL 路径、不隐式启动守护进程。
- ADR 0013 明确增补可选 provider 委托，不赋予 Hub Docker 管理能力。

### 管理员控制的 pirun / 镜像入口

- 在 `/home/fate/docker_files/pi-docker` 增加固定的进程管理器和控制客户端，
  用现有 Python3 或 Node 标准库实现，不新增 sudo/PTY 原生扩展依赖。
- 普通交互式受管 Pi 由管理器启动一个继承终端的子进程；安装、更新、
  help、version、print/RPC 等非本次支持的调用保持原行为，不误进入重启循环。
- 正常 `/quit`、Ctrl+D、宿主终端关闭、显式停止容器均应退出；
  只有已接受的一次性重启操作才能重新启动子进程，禁止无限崩溃拉起。
- 启动器登记稳定 run 身份及受管能力；门控基于管理员允许的镜像、固定入口、
  Compose 标签、运行限制核对唯一容器，不能仅信任浏览器或 Agent 自报的名称。
- 管理器自身和控制入口在镜像内，不放入所有 Agent 可写的共享 home 卷；
  每次运行的控制 socket/恢复记录在该容器私有运行目录中，权限 0700/0600。
- 保持 UID/GID 1000、cap-drop ALL、no-new-privileges、现有卷和工作区边界。

### 现有部署门控

- 增加独立于镜像部署的 `pi-process-restart` 操作类型及审计记录。
- 仅门控持有 Docker socket；它只对核实后的完整容器 ID 执行镜像内的固定
  控制程序，不执行网页或 Agent 提供的 shell，不改变容器运行配置。
- Hub 使用独立的最小权限生命周期申请凭据；不复用共享 pi-gate token，
  不把现有 admin.sock 或全局管理员凭据挂给 Hub/Agent。
- 生命周期策略与服务镜像更新策略分开。默认 disabled，管理员显式启用后，
  已登记的受管 Pi 可对通过网页管理授权的空闲重启请求自动执行。
  Hub 镜像更新的 auto 不隐含授权重启 Pi。
- 启用后的日常手机操作不要求回到电脑审批；管理员仍可切为 manual/disabled。
- 镜像发布与重启共用互斥协调；同一 run 至多一个有效请求，限制频率和队列。

## 5. 网页管理授权

现有 Caddy 全路径登录保持不变，但本地 loopback Hub 没有用户登录，
普通 Pi 也能访问它，因此“能打开会话列表”不能成为重启授权。

增加独立的 Hub 管理解锁：管理员通过 Hub CLI 在受信任终端生成
单次、短期配对码，在网页输入；不在 URL、模型聊天、网页源码或日志中保存秘密。
配对码服务端保存摘要，有过期、失败次数限制和一次性消费。
成功后签发短期 HttpOnly、SameSite=Strict 的管理 Cookie；公网要求 HTTPS/Secure。
管理会话保存在 Hub 私有状态/内存，不进入共享 Pi 卷，支持管理员撤销。

所有重启写操作同时要求有效管理会话、同源 Origin/Host、CSRF nonce、
准确目标 generation 和一次性幂等键。只有 Caddy Basic 登录或猜出路由不足以重启。
配对/重启协议限制正文大小和请求速率；绝不返回 secret 或宿主绝对路径。

管理解锁允许管理本 Hub 下管理员已启用的受管 Pi，不声称实现多租户用户隔离。
相同 UID、共享 home 和同一运行卷也不是恶意 Agent 的完整安全隔离。

## 6. 重启协议和恢复

状态转换：

```text
requested → checking → prepared → stopping → starting → verifying → succeeded
                 ↘ rejected             ↘ failed / recovery_required
```

1. Hub 确认管理员授权，将选定 generation 解析为内部 run 身份，提交门控。
2. 门控核对当前容器身份、管理员策略、固定管理器能力和本次请求幂等键。
3. 管理器与当前扩展完成 prepare：检查 idle、无排队消息、无工具运行、
   compaction、导出、上传或 session 切换等冲突操作；设置重启屏障。
   屏障期间新任务被明确拒绝，不偷偷接收或重放。任何无法可靠判断的状态拒绝重启。
4. 生成只在容器内使用的快照：精确 sessionFile、sessionId、leafId、
   runtimeId、cwd、model/thinking 及安全恢复所需的启动选项。
   浏览器不决定这些字段。无已保存会话或不支持的启动模式直接拒绝。
5. 预检已安装 Pi 的可执行入口及版本；安装未完成、版本读取失败时保留旧进程。
   此预检不证明新版本能成功启动。准备后状态变化必须重新校验或撤销请求。
6. 通过经真实 Pi 验证的优雅关闭路径停止唯一子进程，等待 shutdown 和退出。
   关闭预算 30 秒，超时不 SIGKILL，不启动第二个 Pi，记录 recovery_required。
7. 仅在旧子进程确已退出后，用数组参数、非 shell 方式重新启动已安装 Pi，
   指定原准确 sessionFile，去除冲突的 continue/resume/session 启动选项。
   同步模型配置；不读取 .env、不更改其他卷/凭据。
8. 新扩展在 120 秒内报告新 runtime 身份、实际加载版本和 sessionId/leafId，
   并经 Hub 后端身份挑战完成登记。工作区、session、分支和目标 run 必须匹配。
9. 验证成功才报告 succeeded；换成别的会话、版本不符预检目标或没有登记均不能报成功。
   一次请求只拉起一次新进程，失败不自动循环、不重放最后一条用户消息。

没有已安装更新时允许明确的“重启当前版本”，结果显示“版本未变化”，
不能显示升级成功。磁盘版本与运行版本分开显示，运行版本在进程启动时采集，
不通过之后再次读取已被替换的 package.json 来冒充。

## 7. 浏览器接续与失败

- 主动重启拥有独立、最长 120 秒的操作状态，不粗暴增加所有 WS 故障的等待时长。
- 重启前取得只绑定此 run、旧 runtime 和本次操作的短期恢复凭据；
  成功后只能跟随经验证的准确后继 generation，不能转到“最新在线会话”。
- 保留 generation 退役、撤销和失效链接规则，旧路由不改指其他 Pi。
- 手机临时断网后可在管理会话仍有效时查询持久化操作结果，不重复执行请求。
- 门控/Hub 重启时先核对账本、容器和进程，再恢复状态；不凭重试自动再杀一次。
- 新版本启动失败时保留会话文件与错误摘要，提供人工恢复说明。
  当前共享 pi-runtime 没有独立旧版可执行副本，不承诺自动降级或撤销数据迁移。
- 失败不清理业务卷、共享会话、凭据或其他容器；审计只记身份、版本、阶段及脱敏错误。

## 8. 部署与兼容

现有运行容器没有管理器，不能靠更新扩展或 /reload 补上。
先在隔离镜像/容器验证，再更新镜像、pirun 和门控；新 pirun 自动获得新能力。
旧 Pi 仍能聊天，但显示“需要使用新镜像重新启动一次”，不自动结束它们。
用户另行选择具体旧容器迁移时才执行，保留所有既有数据卷。

Hub 通过现有门控部署新源码和预构建 dist，保持原 Caddy/SSH 隧道及公网入口。
新增 Hub 私有 lifecycle 凭据挂载需要管理员审核并更新门控管理的 Hub 部署模板，
不能绕过封存或混用旧 Hub Compose。新配置仍集中在 docker_files，
门控账本保持在专用卷，不另建 WSL 路由服务或分散到 .local。

## 9. 验收与测试

- 重启授权：无管理登录、只有 Basic 登录、本地 Pi 请求、跨源/CSRF、
  过期配对码、重复 nonce、错误目标、撤销策略全部拒绝；错误不泄露秘密。
- 管理器：普通退出不拉起、同一终端持续可用、真实 Pi 优雅关闭、超时不强杀、
  参数中空格和恶意字符不执行 shell；RPC/安装命令保持兼容。
- 恢复：两个同项目 Pi、不同项目、不同分支、resume 切换竞争，
  确保只有目标重启，sessionId/leafId 正确，不重放工具或消息。
- 生命周期：安装前后版本、相同版本重启、扩展加载失败、启动超时、
  Hub/门控重启、连续请求和安装中的竞争；失败状态不得伪装成功。
- 存储：工作区新文件仍为 fate:fate，原卷身份不变，重启期间不触发附件回收。
- Web：手机宽度确认弹窗、阶段展示、长于 15 秒重启、WS 接续和恢复失败入口；
  遵循仓库真实 Pi E2E 与 webui-visual-check 要求，重建并验证 tracked dist。
- 部署：先使用随机端口、临时卷和测试容器，不重启现有正式 Hub/Pi。
  上线另记录版本、目标和回滚步骤；不得把单元测试当手机实机验证。
