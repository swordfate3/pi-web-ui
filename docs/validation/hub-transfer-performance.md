# Hub 慢隧道传输优化验证

## 诊断与授权范围

维护环境的实际链路为 HTTPS 登录网关 → SSH 反向隧道 → 本机 Docker Hub → Pi。
优化前，同一版本主脚本3,436,535字节：本机44ms，远端经过隧道两次约30.43s和30.37s；
会话列表和HTML只需约38–56ms。120,158字节CSS经隧道约1.37s。
614,649 / 958,657字节的初始消息分别约4.36 / 8.75s，本机约62 / 71ms。
这些结果指向传输量和隧道吞吐，而非已证明的DNS、TLS、CPU、会话文件全量加载或运营商限速。
实际发送已有历史边界，不能把磁盘上的整个大JSONL文件当作首屏传输量。

用户确认本轮仅修改：隧道前静态压缩、严格版本化资源的私有浏览器缓存、
浏览器方向的有界WebSocket压缩。保留登录、跨源隔离、generation失效、动态数据
不缓存、会话/扩展数据和正在运行的Pi进程。不修改Gate策略。

## 实现与自动化验证

- `hub/asset-transfer.ts`：筛选哈希JS/CSS、编码协商、流式br/gzip、私有一天缓存、
  Vary保留和identity表示校验器移除；既有响应头过滤保留。
- `hub/server.ts`：HTTP接入上述 helper；浏览器WS限制context takeover、窗口、
  压缩等级/并发/阈值，本地Pi hop显式不请求压缩；没有改变应用层消息。
  独立审查发现并复现两类协商回归：压缩后端误收到浏览器扩展头会502、较小/缺失窗口
  提议会400。新增4项测试先失败再修复；本地hop单独去除协商头，浏览器只对可满足的
  严格提议启用压缩，其余回退普通连接，不放宽Origin、证明或generation检查。
- 新增真实临时Hub、登记客户端、HTTP和WS后端测试，不改生产进程/端口/凭据。
  新测试先在旧实现8失败/1通过，证实缺失行为，再实现并补上边界测试。
- 压缩字节解码后完全一致；无压缩客户端、q权重/排除、HEAD、CSS、Vary、
  原编码透传、404/206/Range/查询参数/错误MIME/下载/Cookie/隐私策略均覆盖。
  上游中断后下一请求仍成功；过期登记410/no-store；WS两向无context takeover，
  两种客户端均可往返，压缩后的超16MiB输入仍按**解压大小**拒绝1009。
- 完整单测513项：512通过、1原有可选跳过、0失败。新增17项传输测试，
  专项新测试及会话Hub测试46/46。独立源代码安全审查复验无遗留可操作发现；
  审查额外核对720种标准提议组合，200种通过allowlist的提议均满足窗口和禁用context takeover。
- 串行运行真实Pi RPC/WS与独立Hub后端集成11/11通过：两个Pi登记、单个退出不影响另一个、
  Hub重启旧链接失效并重新登记、撤销、portable连接及消息版本恢复。
- 连接TypeScript检查、生产构建和dist/manifest一致性通过。前端输出哈希未变化，
  只更新Hub产物及源码清单；未做浏览器截图、手机实机或完整浏览器E2E。
- 首次普通沙箱测试因不允许监听端口/Unix socket报EPERM；开放本机测试监听后通过。
  首次静态检查仅因新文件格式失败，已仅格式化新文件；不批量修改既有警告。
  补充协商测试时发现已安装ws运行时支持`clientMaxWindowBits:false`、类型声明却不接受；
  最终以显式标准提议头测试相同协议行为，类型检查通过，不使用any或关闭检查。

## 真实资源，本地隔离传输测量

只读取得运行中Pi提供的主脚本，使用本轮真实HTTP压缩 helper 在临时回环端口传输。
每种编码均验证解码后与原文件逐字节相等；不输出脚本正文、消息或凭据。

| 协商编码 | 原始字节 | 实际body字节 | 减少 | 本地一次测量 |
| --- | ---: | ---: | ---: | ---: |
| identity | 3,436,535 | 3,436,535 | 0% | 33.9ms |
| gzip，等级6 | 3,436,535 | 1,019,894 | 70.3% | 73.7ms |
| Brotli，质量4 | 3,436,535 | 990,879 | 71.2% | 58.8ms |

此处为传输body计数，不是只看压缩响应头；不是完整TCP/TLS字节、远端加载时间或
浏览器重复访问缓存命中实测。单次本地耗时包含流传输，不能当作独立压缩CPU基准。
按原吞吐推算主脚本传输时间可明显缩短，但未部署前不宣称远端或手机首屏已加速。

## 发布状态与边界

本地分支 `codex/hub-transfer-performance` 基于公开main的 `53bb63f`。
本报告中的测试/构建不等于发布或部署成功；Git推送、Gate申请、授权、部署完成、
线上新构建身份和公网/手机效果需要分别确认。不要直接用未发布产物替换运行Hub，
不要以本次传输优化为由重启Pi、删除历史、放宽认证或改审批策略。
