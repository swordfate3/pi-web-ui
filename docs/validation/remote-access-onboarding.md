# 远程访问向导与登录管理验证

日期：2026-10-14。分支：`codex/portable-web-connection`。

## 实现范围

- 本地 `/webui-setup`、可跳过首访提示及设置入口；桌面／手机尺寸中英双语。
- 本机、可信 LAN、新 Linux 单会话网关、已有兼容网关四种明确边界。
- 校验后的非敏感浏览器草稿、文件预览／下载；存储拒绝时不虚报成功。
- 实际监听信息通过 typed store intent → 只读 `get_web_connection` 返回，无账号密码／登记凭据。
- 独立服务器终端工具用于 Caddy 首次设置、账号密码修改、忘记密码恢复及真实 HTTPS 登录验证。
- 原子替换、私有备份、并发修改拒绝、完整配置与账号包含关系校验、失败回滚。

测试使用独立临时配置、faux provider 和真实 Pi 进程／WS；没有读取用户会话或给实际 Pi 发送消息。浏览器用例仅在草稿写入错误测试中拒绝该 localStorage key；没有替换 Pi／WS 或注入 React 状态。

真实 Caddy 测试使用 Caddy 2.10.2、回环端口、临时私有 CA 和虚拟账号。CA 仅由测试客户端信任，配置明确跳过系统信任安装；不修改系统证书仓库／实际 Caddy。覆盖匿名 401、新账号 200、旧账号失效、其他账号保留、foreign WebSocket Origin/null 拒绝、真实配置校验／适配／重载、失败回滚及控制终端恢复密码不回显。HTTPS 就绪检查等到临时站点证书生成，不跳过 TLS 校验。

首次后端测试未指定已安装 Pi 可执行路径而无法启动；设置 `PI_E2E_BIN` 后三项复测通过。原始失败不作为产品通过证据。

独立审查发现完整配置的全局处理顺序可让代理绕过认证。新增回归先确认旧检查失败，再实现保守执行路径校验；真实 Caddy 验证 `order reverse_proxy before basic_auth` 和 `order reverse_proxy before respond` 都在重载前被拒绝，站点回滚且原有认证／Origin 保护仍有效。无法证明安全的复杂路由不自动修改。

复审发现另一监听器可能绕过当前站点保护。新增单元回归先复现旧实现接受公共地址 catch-all 的问题，再验证跨服务器检查；真实 Caddy 适配独立绑定地址上的 catch-all 与通配域名，确认重载前拒绝并恢复原文件。其他监听器必须仅有与目标域名不相交的普通 host 匹配；不依赖 DNS 推测，即使端口不同也保守拒绝复杂／无 host 匹配。

最后复审发现认证错误可进入服务器级 `handle_errors` 代理。单元与真实 Caddy 适配测试先同时复现接受不安全配置，再验证选中服务器的非空 error routes 一律拒绝，重载未发生且原文件恢复。完整 41 项浏览器回归后仅更新了可下载 Python 工具的此检查；重建后再次通过两项桌面／手机向导用例。

## 安全和交付边界

密码只在用户自己的服务器终端输入，bcrypt 通过子进程 stdin 生成；不进入网页、模型、脚本正文或命令参数。公开网页没有管理员执行／密码重置 RPC。HTTP 验证使用有效 TLS、拒绝重定向，不将代理／连接失败误报为认证成功。

新部署模板只支持标准 HTTPS 443 的独立单域名／单会话，不创建多会话门户、安装服务或管理防火墙。已有网关保留认证并解释登记／容器挂载要求。脚本支持专用 Caddy 站点文件，复杂共享结构会拒绝；Docker 需目录绑定而非单文件绑定。已有部署没有被改动。

网页生成材料仍是“待执行”；终端 `APPLIED` 和真实 HTTP `VERIFIED` 分开，后者也不宣称 WebSocket、路由租约或手机可达。共享 Caddy 会重载，相关会话受影响，回滚重载失败要求管理员检查。

构建仍有项目原有大 chunk 警告，Node 测试仍有 module-type 推断警告；本次不扩大到包模块模式或整体打包优化。
